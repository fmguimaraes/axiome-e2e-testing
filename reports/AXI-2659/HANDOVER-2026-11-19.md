## 1. What the feature is

The source document is ADR-002, `axiome-docs/.../ADR-002-Surfaces-Own-Their-Flow-Not-The-Principles.md`, ruled by the owner on 2026-11-17. The specs are linked below.

**The problem.** The Investigator (SAP) surface had built its own copies of the platform's principles:

| Copied principle | What the SAP path used instead |
|---|---|
| Analysis | `SapRun` |
| Rules | A `choice`-only parameter filter |
| Evidence and publish | `SapQuestionReview`, `SignOff` and `RunReport` |
| Semantic profile | `dataSpecification` |

Every new capability (multi-file, stratify, extra figures) then had to be re-implemented for the SAP path.

**The rule.** A surface owns its flow and presentation, never a copy of the principles: analysis, evidence (sign = publish), rules and semantic profile. The Investigator keeps its own UI (home, study page, rail, question and result page, download menu). The owner said this UI is good: never redesign it and never swap in wizard pages. Only rewire it onto the shared APIs.

**The concrete rulings:**
- 1 plan question = 1 ordinary analysis, launched through **known actions** via guided-analysis `plan/compile`. Never build a parallel compiler.
- Partial and full launch are both allowed.
- A plan change makes a new version that supersedes the old questions. Unchanged questions carry forward.
- The data spec IS the semantic profile (same format). A study inherits it, and users can extend it in any project.
- Recommended chart types are built from the MAG4 reference charts:
  - group comparison (MWU, KW);
  - stratified post-hoc (one Dunn run, with stratum as `featureColumn`).
- A hand-made custom chart over the analysis snapshot is still a use case (D27).
- **D28, no new machinery.** The only new capability allowed is translating a saved template into the known actions a person does by hand: run rule, snapshot, chart, save evidence, publish.
- There is no backward compatibility for SAP runs. The old tables stay in place but unread, with no migration (lead ruling L1).

**Owner acceptance has three parts:**
1. Finished explorer and wizard analyses show in the Investigator UI.
2. An Investigator-launched analysis opens in the classic explorer, one analysis per question.
3. A custom chart over a question's snapshot is saved as evidence and published alongside the recommended chart.

### Fixes made this session (uncommitted)

1. **`playwright.config.ts`.** Added the project `axi-2659-plan-to-four-images`, with `testMatch` set to the spec and no `setup` dependency. The spec is excluded from the `chromium` project's `testIgnore`. This mirrors `axi-2647-adr002`. Without it, the shared `setup` project fails ("login failed for non-self-registering role admin") and nothing runs.
2. **Upload race in `.6`.** `useExisting()` now waits up to 10s for the async `upload-duplicate-use-existing` banner. It used to check `.count()` synchronously.
3. **Wrong project landing.**
   - **Cause.** The `/investigator` index route has no `:projectId`. `countRule()` (`axiome-front/src/lib/investigatorScope/countRule.ts`) picks the stored choice from **sessionStorage**, which `lastStudy.ts` reads:
     - `axiome-investigator-last-workspace`
     - `axiome-investigator-last-project`

     With no stored choice, it falls back to the alphabetically-first enterable project. That is the demo "CeRAINOM-IgG4 …" project, not the test's "E2E AXI-2659 …" one.
   - **Fix.** `signInBrowser()` now sets both sessionStorage keys. The localStorage `axiome-active-*` keys belong to a different, team-surface concept.
4. **Reload race in `.7`.** Both polling loops used `page.reload()`, which aborts when the SPA is mid-navigation. `expect.poll` does not retry a thrown error, so it failed instantly. Both loops now use `page.goto(`${BASE_URL}/investigator`, { waitUntil: 'load' })` inside try/catch, and a throw counts as "not ready yet". The temporary DEBUG block was removed.
   - **Not yet verified by a run.**

**Why it stopped.** The worktree has no `.env` (untracked). The previous session was not permitted to read or copy `.env` files, so runs 7 and 8 skipped all 17 tests: `test.skip` in `beforeAll` fires when the env vars are missing.
